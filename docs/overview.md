# Vasest — Kinmokusei testing framework

Vasest is a testing framework for applications and libraries written in Kinmokusei. Its goal is to let developers write, run, and understand tests in Kinmokusei without maintaining handwritten Go test files for ordinary application behavior.

## Intended experience

- Discover test files in a project and run all files or one selected file.
- Provide assertions for equality, truth values, errors, and expected failures.
- Report cyclic, deeply nested and large values with bounded diagnostic traversal, preserving native comparisons, ordinary value formatting, cleanup and later-case execution.
- Offer typed `expect(value).toEqual(...)`, `toBe(...)`, and `toBeNil()` matchers with `.not`, inspired by [Jest](https://jestjs.io/docs/expect) and implemented independently for Kinmokusei.
- Express domain-specific checks with `expect<T>(value).toSatisfy(predicate)` and `.not`, preserving typed callback parameters, one invocation per check, throws, runtime skips and native panic cleanup.
- Compare ordered native types with `expectOrdered<T>`, strict/inclusive comparisons and `.not`, retaining integer precision, numeric widths, nominal types, string ordering and floating-point semantics.
- Check native `float32`/`float64` and nominal floating-point types with `expectFloat<T>`, explicit absolute tolerances, NaN/finite properties and `.not`, preserving native subtraction and rounding with optional inference and direct constructors.
- Verify typed function/action mock calls with `expectMock<A>`, count/argument/Nth/last matchers and `.not`, plus typed call-argument predicates with short circuit evaluation, reading one live history snapshot per check without invoking the dependency.
- Reset reused function/action mocks with an explicit typed replacement, atomically clearing queued behavior and histories while preserving active callback execution and isolating its discarded outcome from new calls.
- Configure native throws on function/action mocks with `throwError` and FIFO `throwErrorOnce`, preserving error references, nil payloads, mock argument/return types, captured active implementations and queued behavior.
- Verify function-mock returns with `expectMockReturn<R>`, count/value/Nth/last matchers and `.not`, plus typed return predicates that skip non-return states, preserving return types and invocation order.
- Inspect shared function/action completion and throws with `expectMockOutcome`, outcome counts, any/Nth/last native error predicates, Nth/last messages, and native cause and type checks with explicit or inferred extraction destinations, retaining native exceptions, void completion and pending/panic distinctions.
- Check mock throw types and extracted contents with any/Nth/last `ThrownTypeSatisfying<T>` matchers and `.not`, supporting explicit types and typed callback bindings, one outcome snapshot, fresh native extraction destinations and unchanged callback control flow.
- Preserve native Kinmokusei types with explicit generic arguments and matcher constructors; provide statically typed string and slice operations through `expectString` and `expectSlice<T>`.
- Check literal string prefixes and suffixes with `toStartWith`/`toEndWith` and negation, preserving native byte comparisons, quoted diagnostics, constructors and typed method bindings.
- Check typed slice elements with `toSatisfyAny` and `toSatisfyAll`, aggregate negation, short circuit evaluation and native callback control flow; explicit types and slice matcher constructors remain available.
- Compare typed slices with `toEqualUnordered` and `.not`, ignoring outer order while retaining duplicate counts, native deep element equality, nested order and nil-versus-empty distinctions without mutating either input.
- Require a typed subset of slice elements with `toContainAll` and aggregate negation, allowing extra elements while counting duplicate requirements and preserving native deep equality, original types and optional inference.
- Verify map key presence, typed entries and length with `expectMap<K, V>` and `.not`, preserving comparable keys, native key identity and deep value equality; `toHaveEntrySatisfying` checks a selected native value with a typed predicate and preserves callback control flow.
- Require a typed subset of map entries with `toHaveEntries` and aggregate negation, allowing extra entries while retaining native key lookup, deep value equality, nil/empty requirements and optional inference.
- Check whole maps with typed `(key, value)` predicates through `toSatisfyAny`/`toSatisfyAll` and aggregate negation, retaining native entry iteration, NaN-key values, short circuit evaluation and unchanged callback control flow with optional inference.
- Inspect native error chains with `expectErrorValue`, cause matching, typed extraction and negated type checks, preserving Go's error interface and custom matching behavior.
- Check an extracted error's type and contents together with `toMatchTypeSatisfying<T>` and `.not`, supporting explicit types and typed callback bindings while preserving native `errors.As` selection and callback control flow.
- Check thrown Kinmokusei errors with `expectFunction`, message/cause/type matchers and negation, invoking each callback once after argument validation and preserving native panic cleanup.
- Inspect thrown function errors with `toThrowSatisfying` and `.not`, passing the original native error to a typed predicate once per throw and preserving predicate throws, skips, locations and native panic cleanup.
- Verify a function's throw type and extracted contents together with `toThrowTypeSatisfying<T>` and `.not`, invoking the body once and the typed predicate only after native `errors.As` succeeds; explicit types and callback bindings remain available.
- Retry assertions with `waitFor` or return a native typed result with `waitForValue<T>`, keeping fresh reads, typed predicates and callback failure locations while stopping immediately for runtime skips and after an expired wait.
- Register typed indexed test tables with distinct names for repeated values and original zero-based indices retained through filtering, shuffling and reruns, including per-row contexts, per-row fixtures and shared fixtures; explicit generic arguments remain available.
- Disable or plan typed tables with `skipEach`/`todoEach` and indexed variants on ordinary and shared-fixture suites, retaining atomic name validation, native row types and ordinary selection/reporting rules without preparing inactive fixtures.
- Report each test's result and failure location, then return a nonzero exit status when tests fail.
- Support setup and cleanup for tests that use temporary files or external resources.
- Prepare and inspect per-case resources in `beforeEachWithContext` and `afterEachWithContext`, sharing one fresh context with the body and fixture setup; typed shared-fixture hooks retain the fixture type and per-case cleanup lifetime.
- Keep tests usable in CI and from an editor or terminal.

The implementation provides named suites and parameterized test rows with optional per-row contexts, assertions for equality, errors and wrapped error identity/type extraction, text, regular expressions, and approximate numbers, typed function and action mocks with call and outcome expectations and queued behavior, string and JSON snapshots, retrying assertions, explicit failure, skipped/todo cases, reasoned runtime skips with case/shared fixture cleanup, recursive test-file discovery, per-test failure continuation for thrown Kinmokusei errors, optional `--bail` and `--fail-on-todo`, per-file timeouts, seeded file and test shuffling, CI file sharding, bounded repeated test execution with sticky failures and failure-history unions, bounded parallel file execution with serialized compilation and ordered output, content-based watch mode with debounced reruns, per-file generated-Go statement coverage with retained raw data and profiles, optional per-executable source/output/report artifacts and coverage HTML tied to archived sources, text, JSON Lines, and JUnit XML reporting with case, suite, and file durations, `beforeAll`/`afterAll` and `beforeEach`/`afterEach` hooks, versioned project configuration with CLI overrides and recoverable watch reloads, relative include/exclude file patterns applied before sharding, case-sensitive test-name filtering, versioned failure snapshots and exact failed-case reruns with suite/file fallbacks, a concise `runSuiteAndExit` entry point, per-test contexts with registered cleanup and scoped directory/environment fixtures, reusable typed setup for individual cases and table rows, typed suite-wide fixtures and shared registered cleanup, disposable-directory and temporary-environment fixtures, and CI-friendly exit codes.

## Boundaries

Vasest owns the test API and runner. Kinmokusei's compiler and package tools provide source checking, compilation, and dependency resolution. A future `keika test` command could invoke Vasest, but that integration is not required for an initial standalone runner.

Framework-specific helpers belong with their frameworks. For example, Kranbelk can provide an HTTP test client and response assertions on top of Vasest. Its `kranbelk test` command should eventually run the project's Vasest tests; today it only checks the application and runs a fixed smoke test.

## First implementation milestone

The `*.test.km` convention, assertion API, discovery, and execution are implemented. Passing, failing, and invalid-source cases are verified from an external Kinmokusei project. A suite reports its test names and assertion messages; the runner reports its file paths and continues to the next file after an execution or compilation failure. A test file that exits without running a suite is reported as failed.

Automatic `.km` source line reporting needs support from the Kinmokusei compiler: its current emitted Go has no source-line directives or mapping back to Kinmokusei. Vasest now records an assertion's actual runtime call site as a Go location, recognizes `.km` positions when line directives are available, and lets test authors attach explicit positions with `withTestLocation`. The location source distinguishes these cases rather than presenting a generated Go line as a Kinmokusei line. Individual failure entries identify setup, body, hook, fixture, and registered cleanup errors in execution order; text and JUnit label these phases and available locations, and JSON preserves each original message and position. Coverage currently measures each test executable's generated Go, including application code imported into that package. Compiler support is still needed for `.km` coverage mapping and reliable project-wide aggregation across distinct generated executables; separate profiles are intentionally retained. Optional artifacts preserve each executable's generated source before another build overwrites it, along with output and raw reports, and provide source-backed coverage HTML. Kranbelk can also add HTTP assertions and delegate its `test` command to Vasest.
